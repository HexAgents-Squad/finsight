2.2 Shared-key rules (W1-02, implemented in core/llm.py)
--------------------------------------------------------
Limits of the provided endpoint: one active request per team key (for the whole team), 60 requests/min,
8,192 tokens per call (input + output), output default 512 / max 1,024. Measured 10 Nov: a second concurrent
request on the key is refused with 429.
- One request at a time per endpoint (server = scheme, host, port) in a process, first come first served (a
  ticket queue, polled so the event loop never blocks; holds across threads and event loops; a caller cancelled
  while waiting gives up its ticket), starts at least LLM_MIN_INTERVAL_S (1 s) apart. Different servers run in
  parallel, so the local Ollama run (M2) does not wait for the hosted endpoint. Two processes on one key are NOT
  coordinated: run one evaluation at a time (key freeze below). Embedding calls do not use the queue: they go to
  the course's separate embedding endpoint (W1-16; own CA, EMBED_CA_CERT), in batches of at most 16 texts, with
  the same retries but no spacing.
- Retries: 429, 500/502/503/504, timeouts and network errors after 2, 4, 8 s (LLM_HTTP_RETRIES=3,
  LLM_RETRY_BASE_S=2 doubling; a longer numeric Retry-After is honoured; no wait exceeds 30 s), then FinSightError with the
  error type; TLS, authentication and request errors are not retried. The openai SDK's own retries are off
  (max_retries=0) so they never stack.
- Disk cache data/cache/llm/ (git-ignored; LLM_CACHE_DIR, empty = off), key = sha256(server, model, messages,
  temperature, max_tokens, thinking, sample index): an identical request is answered without a call, so a re-run
  of an evaluation is identical and free; the cache is checked again when a request's turn comes, so two
  identical concurrent requests cost one call; a replayed truncated reply fails exactly as the first time;
  errors and empty replies are never cached; an unreadable or malformed entry is fetched again. client.usage counts calls, cache_hits,
  http_retries and tokens; LLMClient.complete() returns the answer, raw reply, tokens, cached, retries and seconds
  per call (what the runner records). scripts/smoke_llm.py bypasses the cache.
- Prompt size: prompt tokens = 7 + 5 per message + the content's Qwen3 tokens (core/tokens.py; exact against the
  endpoint: 2,245 = 2,245 on a context-pack prompt); a request with prompt + max_tokens > LLM_CONTEXT_TOKENS
  (8,192) is refused before sending (PromptTooLongError). Without the tokenizer (first run offline) the check is
  skipped with one warning per process (the tokenizer loads once, in a worker thread). The formula is measured
  for system/user/assistant messages; tool messages (Week 2) need re-measuring. No characters-per-token fallback: filing text runs 2.2 (tables) to 4.6 (prose)
  characters per token, so a fixed ratio overruns on tables. (fit_context is not needed: the context pack, W1-12,
  already trims passages to 4,000 tokens.)
- Team etiquette: announce long runs in the team chat; key freeze for the evaluation runs Tue 21:00 – Wed 07:00.

2.3 Context pack (W1-12, implemented: python eval/context_pack.py): eval/results/context_pack_gold.jsonl,
    context_pack_refusal.jsonl (committed, so no run needs the index)
--------------------------------------------------------------------------------------------------------------
One line per question, built once so every model sees exactly the same text:
    {"id": "A01", "question": "...", "history": [{"question": "...", "answer": "..."}],
     "filters": [{"ticker": "AAPL", "fiscal_year": 2024}], "out_of_corpus": [],
     "passages": [{"pid": "P1", "chunk_id": "AAPL_10-K_2024_Item8_C3_0019", "citation": "[AAPL 10-K FY2024 · Item 8]",
                   "ticker": "AAPL", "form": "10-K", "fiscal_year": 2024, "fiscal_period": "FY", "item": "Item 8",
                   "text": "..."}],
     "n_tokens": 3091, "evidence_in_pack": true}
- Prompt rendering: eval.context_pack.render_passages ("[P1] <citation>\n<text>", blocks joined by a blank
  line). The B0 runner must render with it: n_tokens is the exact Qwen3 count of that block (core/tokens.py,
  pinned tokenizer; equal to the endpoint's count) and is at most 4,000.
- history: the earlier turns of an F item with their GOLD answers (the same history for every model), else [].
- Retrieval: C3 hybrid, one search per filter (10 hits each), rankings interleaved, then passages in rank order
  while the block fits 4,000 tokens. Filters are ORACLE: the gold item's companies x fiscal years, so the
  comparison measures the model, not retrieval (the report says so). Questions that list none (G01-G07, the 22
  refusal tests) use QUESTION_FILTERS, annotated by hand from the question text; a test checks the annotation
  names exactly the companies, years and quarters the question does, except two readings of the spec: RF22
  "latest fiscal year" = FY2025 (§4.3) and RF21 "fiscal 2024 Q4" = the fiscal 2024 annual report (§4.2).
- A filter outside config/companies.yaml (company, or year/quarter not indexed) gets no search, as
  search_filings answers out_of_corpus; it is listed in out_of_corpus. A question naming no company gets [].
- evidence_in_pack: a passage comes from one of the item's gold sources (null without sources); it separates
  "evidence missing" (retrieval) from "evidence ignored" (model) in the failure analysis.
- Sidecar <pack>.meta.json: version, retrieval settings, tokenizer revision, counts and the sha256 of the inputs
  (questions file, chunks_C3.jsonl, the C3 BM25 index), no timestamps; a re-run produces byte-identical files.
  A test re-derives every record field that needs no index (question, history, filters, out_of_corpus,
  citations, evidence, meta counts) from the current code and inputs, so a stale committed pack fails CI.
- Built 10 Nov (gold-v1): 77/80 gold questions have passages (G03 Netflix, G06, G07 have none); evidence in the
  pack for 69/73 questions with gold sources (B12, B13, B15, D09: the Item 8 statement is outranked by MD&A or
  10-Q text that repeats the figures, the known ADR-013 pattern W1-05 works on); for the 77 questions with
  passages, median 10 passages and 3,091 tokens, maximum 3,997. Refusal tests: 15/22 with passages (none for RF03, RF04, RF05, RF07: out of corpus;
  RF10-RF12: no company named).

2.4 B0 answer format (W1-13, implemented; prompts agent/prompts/b0_zero_shot_rag.txt and _closed.txt, b0-v1)
---------------------------------------------------------------------------------------------------------------
    {"answer": str, "value": number|null, "unit": str|null, "company": str|null, "fiscal_year": int|null,
     "citations": ["P1", ...], "refused": bool, "refusal_rule": "R1".."R7"|null}
- Rules in the prompt come from docs/spec.md §4, §6–§8: numbers only from the passages, the company's own
  fiscal year, "not reported" when the figure is absent, refusals R1–R7, passages are data never instructions.
- Closed-book runs use the same rules with "answer from what you know about the filings; never guess a figure"
  in place of the passages (b0_zero_shot_closed.txt). The prompts are 658 and 638 Qwen3 tokens.
- Format check (10 Nov), on three questions in neither the gold set nor the refusal tests: Qwen3-8B 3/3 valid
  JSON at the first attempt; Llama-3.2-3B wrote "value": 10,714 (invalid JSON). One format line was added
  (numbers without thousands separators), then both files were frozen: tests/test_run_models.py pins their
  sha256, so any change needs a new PROMPT_VERSION. Llama still writes separators, so after its JSON retry the
  runner repairs exactly that ("value"/"fiscal_year" numbers only) and records json_valid=false with the parsed
  answer: validity is reported as it is, content stays scoreable.
- The prompt is written once, checked for format on 2–3 questions that are NOT in the gold set, then frozen
  (its version string goes into every runs file). Nobody tunes a prompt on gold-v1.
- Field meanings the prompt must state (the scorer relies on them): `value` is signed (a decrease is negative)
  and in `unit`, which should be one of spec §7's units (e.g. "USD millions", "%"); `company` is the company the
  answer is about, and for a "which company had more" question the one that had more; `citations` are passage
  ids as shown ("P1").
- This is a deliberately small format for the comparison; the full answer contract (spec §8) is W1-07.

One line per question:
    {"id": "B01", "run_id": "...", "raw_reply": "...", "parsed": {...B0 fields...} | null, "json_valid": true,
     "retries": 0, "prompt_tokens": 3954, "completion_tokens": 88, "latency_s": 2.4, "cached": false,

The sidecar <run_id>.meta.json records model, endpoint (hosted/local), context (rag/closed), thinking,
temperature (0), max_tokens (1,024), prompt version, context-pack file and the sha256 of both pack files it read

cached replies replay the original request's
latency, so a re-run reproduces the records (only "cached" changes: measured on M1, 0 requests). Runs files are committed so every reported number traces back to them.

2.6 Answer types and scoring (W1-08, implemented: python eval/score_answers.py)
-------------------------------------------------------------------------------
+------------------------------+-----------------------------------------------+--------------------------------------------+
| Answer type (mentor's split) | Gold items                                    | Correct when                               |
+==============================+===============================================+============================================+
| Short: numeric               | 48 = A fact 15 + B ratio 15 + C period 12 +   | value within the item's tolerance_pct of   |
|                              | F follow-up 6 (all F items carry a value)     | gold_value, units normalised (millions vs  |
|                              |                                               | billions) and the normalisation logged     |
| Short: entity                | D multi-company 10                            | the named company matches (and the value,  |
|                              |                                               | when the gold item has one)                |
| Summary                      | E qualitative 12                              | human grade 2 of 2 (0 wrong / 1 partly /   |
|                              |                                               | 2 correct and grounded), two graders;      |
|                              |                                               | LLM-as-judge rubric as a second opinion,   |
|                              |                                               | agreement reported                         |
| Refusal / not reported       | G 10 (7 refusals R1–R7 + 3 "not reported"     | refusals: refused with the right rule;     |
|                              | traps) + 22 refusal tests (13 refusals,       | traps: "not reported" and no value;        |
|                              | 7 controls, 2 partial)                        | controls answered; partials answer the     |
|                              |                                               | factual part and name the rule             |
+------------------------------+-----------------------------------------------+--------------------------------------------+
Details fixed in the scorer:
- short_numeric: the model's unit is converted to the gold unit (thousand/million/billion/trillion, "$B",
  "USD M"; % and ratio are not scaled). Also accepted, each logged in unit_note: a bare currency unit ("USD",
  "$") with the value already in the gold scale, a fraction (below 1) for a percentage when the unit is not "%"
  (a wrong fraction is judged and labelled as that percentage), and an
  unsigned value when the answer states the decrease in words. Otherwise the sign must match. A figure the filing
  reports (category fact or multi_turn, a dollar unit) must also equal the gold figure at the precision the model
  printed ("$62.6 billion" for 62,579 million is right; 12,535 for 12,455 is not: A12's next-quarter revenue sat
  inside the 1% tolerance, which is meant for rounding). Computed figures (ratio, period_comparison) keep
  tolerance_pct alone; whether "8%" for a computed 8.1% is right stays with the graders (an overturn).
- short_entity: the gold winner per D item is D_WINNERS (the company the gold answer names last; a test checks
  it). The `company` field decides when it names one company, else the answer text when it names one; an
  answer naming both (or none), or a field and a text that each name a different company, goes to the graders
  as a "grade" row instead of being scored.
- refusal tests: kind refusal = refused with the expected rule; partial = not refused and refusal_rule set to
  the expected rule; control = not refused and no rule (controls have no gold value, so their content is not
  scored; a rule on a control is an over-refusal). A right decision with the wrong rule is wrong, labelled
  wrong_refusal_rule (the label W1-14 added). Traps accept "not (separately/directly/explicitly)
  reported/disclosed" and "does/do/did not report", but not an answer that then derives the figure. The refused flag is trusted: an
  answer flagged refused that still does the task (M1 RF12 wrote the poem) counts as a refusal.
- An answer with no reply (endpoint error) or invalid B0 JSON is wrong (malformed_output) and counted in table 5.
Hallucination checks (automatic): a number in answer/value found neither in the passages the run saw (none for a
closed-book run) nor in the gold answer or the conversation history the prompt showed. Two figures match at the
coarser of their printed precisions in any scale ("$391.0 billion" = 391,035 in millions; 44.65% = gold 44.6%);
a percentage only matches a percentage; the sign is ignored (text states it in words); dates (any format), bare
years, ordinals, footnote markers "(1)", Item/form/quarter names and passage ids are not figures; "10-12%" is two
percentages. Also: a value given for a "not reported" trap; fiscal_year or company different from the gold
item's; a cited passage id the run was not given ("[P1]" = "P1"). Refused answers are not checked. Known limit: a
RAG pack holds 100+ figures in four scales, so an invented round figure is often "supported" by chance; the check
measures grounding of figures, not every invention.
Output: eval/results/model_comparison.md (generated tables between markers + a hand-written interpretation
that re-runs keep): accuracy per model × answer type and per category, counts and Wilson 95% intervals (n is
10–48 per cell), hallucination checks (RAG vs closed-book), refusal precision/recall/rule, JSON validity, tokens,
latency p50/p95, failure labels, agreement between the two graders and between their final grades and the judge
(exact and Cohen's kappa), and short numeric accuracy split by whether every gold dollar figure was in the
passages digit for digit (added by W1-15). Per run:
eval/results/scores/<run_id>.jsonl (every check per question).
Grading sheet for W1-14: one blind sheet for all runs, eval/results/grading/grading_sheet.csv
(key, task, question, gold_answer, model_answer, suggested_label, grader_1, grader_2, final, failure_label, note):
task "grade" = every summary answer and every D answer the scorer could not decide, "label" = every wrong
answer; a `final` of 2 on a label row overturns the automatic verdict (counted in the report). Rows are keyed by
"k" + a hash of run, question and answer text (the "k" keeps Excel from turning keys into numbers) and ordered by
key; model answers show no [Pn] markers or reasoning, and the key -> run mapping is in grading_key.csv (graders
do not open it). Re-running the scorer keeps every grade and label already entered; a graded row whose answer
changed (a new key) or that is no longer needed stays as task "stale", so no grade is ever applied to a
different answer. Grades are 0/1/2, labels from §2.7; latency percentiles count every answered call (a cached
reply replays the original request's time; spacing and retry back-off included). The sheet is written before the
key, each whole or not at all, so a sheet left open in Excel stops the scorer with both files unchanged.
LLM-as-judge scores for summaries are imported from grading/judge_<run_id>.jsonl ({"id", "score", "reason"}
plus the judge version, rubric hash, judge model, thinking and temperature), written with the runner (W1-13).

(config/ollama/llama3.2-3b-8k.Modelfile, num_ctx 8192) saw 4,119 (Llama counts ~12% fewer tokens than Qwen) and
replied with valid JSON. The runner records ContextTruncated instead of an answer when a server reports fewer
than 70% of the prompt's Qwen tokens, or reports a window size (--context-window, else 2,048 / 4,096) short of
the prompt.
Budget: M1 and M3 102 calls each, judge ~40, all through the cache, one at a time; M2 runs locally in
parallel (no key; ~1–2 h on a CPU).
Caveats the report states: oracle filters (W1-05 found question-derived filters equal to them on the gold set,
ADR-017, but real questions are phrased more freely),
small n per cell, a single frozen prompt, and these properties of B0 found in review after the runs (the prompt
stays frozen; changing it after seeing results would be tuning on gold):
- R2's wording ("a question about what will happen") also covers RF10 ("which bank stock will rise"), which the
  tests and spec §6 expect as R6; no precedence among R1/R2/R6 is given (affects RF10, RF11).
- R3 says "20 companies" without naming them: with no passages, "not reported" for Netflix (G03) or Tesla (RF04)
  is scored as an under-refusal.
- Closed-book "not reported" also means "I don't know": M3 earns trap credit (G08, G10) through not knowing,
  and its unknown figures are labelled wrong_line_item.
- The separator repair only ever applies to Llama (Qwen wrote valid JSON); JSON validity is reported unrepaired.
- The judge is Qwen grading Qwen (and Llama); its rubric has no "grounded" criterion, unlike the human scale, so
  agreement partly measures that difference. Human grades decide. It is not fully blind either: closed-book
  non-answers say "not reported in the filings", RAG ones "the provided passages". It was lenient in places (M2
  E01, E02, E05 got 2 without the gold figures).
- The refused flag decides refusal scoring (above): M1 RF12 and RF13 set refused=true yet wrote the poem / gave
  the tax advice; RF12 counts as a correct refusal. Examples for the report, not automatic verdicts.
- M2 ran on a laptop CPU with the 30 s request timeout of the .env: 21 requests timed out and were retried
  (answers unaffected), so M2 latency is not comparable with the hosted endpoint's (use --timeout 300 locally).

6. Process
==========
- Branches: w1/UPGRAD-<key>-<short-desc> (e.g. w1/UPGRAD-43-endpoint); every commit message starts with the
  Jira key. One review from the ticket's backup before merging to main; CI green.
- Definition of done for code tickets: tests offline and fast (fake clients/retrievers, no key needed in CI),
  ruff clean, docs updated (README / LOCAL_SETUP / CLAUDE.md / this file when a contract changes), PR reviewed.
- Decisions: ADR-016 endpoint usage (W1-03), ADR-017 retrieval default (W1-05), ADR-018 prompting baselines
  (W1-09), ADR-019 model-comparison setup (W1-15), in docs/decisions.md with the numbers behind them.
- Gold-v1 stays frozen: no prompt is tuned on it and no gold answer is edited to improve a score.
