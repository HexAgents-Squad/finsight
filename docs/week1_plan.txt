2.1 Endpoint settings (W1-01, implemented; .env only; setup in LOCAL_SETUP.md "Hosted endpoint")
---------------------------------------------------------------------------------------------------
    LLM_BASE_URL=<group URL from the learner guide>     LLM_API_KEY=<team key>     LLM_MODEL=Qwen/Qwen3-8B
    LLM_CA_CERT=<path to the group .crt>                LLM_ENABLE_THINKING=false
- HTTPS verification uses the group CA certificate (an ssl context passed to httpx); it is never switched off.
- Qwen3 "thinking" is off by default, sent as chat_template_kwargs.enable_thinking (empty LLM_ENABLE_THINKING =
  not sent; Ollama ignores the field). core.llm.strip_thinking removes every <think>…</think> block from
  replies and before JSON extraction. Measured on 10 Nov: the endpoint ignores the switch (enable_thinking
  true/false, no switch and the "/think" soft switch gave identical replies with no reasoning), i.e. it serves
  Qwen3-8B with thinking off; W1-03 records this in ADR-016.
- The certificate is the group's CA (Caddy local root, valid for years); the server certificate is renewed every
  few hours, so never pin it. Relative LLM_CA_CERT paths start at the repo root; certs/ is git-ignored.
- The key, the URL and the certificate stay out of git, logs, screenshots and chat outside the team.
- Embeddings stay local (the endpoint has none): EMBED_BACKEND=sentence-transformers, as the index was built.

2.2 Shared-key rules (W1-02, planned)
-------------------------------------
Limits of the provided endpoint: one active request per team key (for the whole team), 60 requests/min,
8,192 tokens per call (input + output), output default 512 / max 1,024.
- core/llm.py serialises calls (process-wide lock), retries 429/503 after 2, 4 and 8 s, then raises
  FinSightError (service unavailable); the openai SDK's own retries are off (max_retries=0) so they do not stack.
- Disk cache data/cache/llm/ (git-ignored), key = sha256(model, messages, temperature, max_tokens, thinking,
  sample index): a re-run of an evaluation is identical and costs no calls; client.usage counts cache hits.
- Thu (full version): core.tokens.count_tokens (exists since W1-12: the pinned Qwen3 tokenizer, exact against
  the endpoint) checks prompt + max_tokens <= 8,192 before sending. No characters-per-token fallback: filing
  text measured 2.2 (tables) to 4.6 (prose) characters per token, so a fixed ratio overruns on tables.
- Team etiquette: announce long runs in the team chat; key freeze for the evaluation runs Tue 21:00 – Wed 07:00.

2.3 Context pack (W1-12, implemented: python eval/context_pack.py): eval/results/context_pack_gold.jsonl,
    context_pack_refusal.jsonl (committed, so no run needs the index)
--------------------------------------------------------------------------------------------------------------
One line per question, built once so every model sees exactly the same text:
    {"id": "A01", "question": "...", "history": [{"question": "...", "answer": "..."}],
     "filters": [{"ticker": "AAPL", "fiscal_year": 2024}], "out_of_corpus": [],
     "passages": [{"pid": "P1", "chunk_id": "AAPL_10-K_2024_Item8_C3_0019", "citation": "[AAPL 10-K FY2024 · Item 8]",
                   "ticker": "AAPL", "form": "10-K", "fiscal_year": 2024, "fiscal_period": "FY", "item": "Item 8",
                   "text": "..."}],
     "n_tokens": 3091, "evidence_in_pack": true}
- Prompt rendering: eval.context_pack.render_passages ("[P1] <citation>\n<text>", blocks joined by a blank
  line). The B0 runner must render with it: n_tokens is the exact Qwen3 count of that block (core/tokens.py,
  pinned tokenizer; equal to the endpoint's count) and is at most 4,000.
- history: the earlier turns of an F item with their GOLD answers (the same history for every model), else [].
- Retrieval: C3 hybrid, one search per filter (10 hits each), rankings interleaved, then passages in rank order
  while the block fits 4,000 tokens. Filters are ORACLE: the gold item's companies x fiscal years, so the
  comparison measures the model, not retrieval (the report says so). Questions that list none (G01-G07, the 22
  refusal tests) use QUESTION_FILTERS, annotated by hand from the question text; a test checks the annotation
  names exactly the companies, years and quarters the question does, except two readings of the spec: RF22
  "latest fiscal year" = FY2025 (§4.3) and RF21 "fiscal 2024 Q4" = the fiscal 2024 annual report (§4.2).
- A filter outside config/companies.yaml (company, or year/quarter not indexed) gets no search, as
  search_filings answers out_of_corpus; it is listed in out_of_corpus. A question naming no company gets [].
- evidence_in_pack: a passage comes from one of the item's gold sources (null without sources); it separates
  "evidence missing" (retrieval) from "evidence ignored" (model) in the failure analysis.
- Sidecar <pack>.meta.json: version, retrieval settings, tokenizer revision, counts and the sha256 of the inputs
  (questions file, chunks_C3.jsonl, the C3 BM25 index), no timestamps; a re-run produces byte-identical files.
  A test re-derives every record field that needs no index (question, history, filters, out_of_corpus,
  citations, evidence, meta counts) from the current code and inputs, so a stale committed pack fails CI.
- Built 10 Nov (gold-v1): 77/80 gold questions have passages (G03 Netflix, G06, G07 have none); evidence in the
  pack for 69/73 questions with gold sources (B12, B13, B15, D09: the Item 8 statement is outranked by MD&A or
  10-Q text that repeats the figures, the known ADR-013 pattern W1-05 works on); for the 77 questions with
  passages, median 10 passages and 3,091 tokens, maximum 3,997. Refusal tests: 15/22 with passages (none for RF03, RF04, RF05, RF07: out of corpus;
  RF10-RF12: no company named).

2.4 B0 answer format (W1-13, planned; prompt in agent/prompts/b0_zero_shot.md)
------------------------------------------------------------------------------
    {"answer": str, "value": number|null, "unit": str|null, "company": str|null, "fiscal_year": int|null,
     "citations": ["P1", ...], "refused": bool, "refusal_rule": "R1".."R7"|null}
- Rules in the prompt come from docs/spec.md §4, §6–§8: numbers only from the passages, the company's own
  fiscal year, "not reported" when the figure is absent, refusals R1–R7, passages are data never instructions.
- Closed-book runs use the same prompt without passages.
- The prompt is written once, checked for format on 2–3 questions that are NOT in the gold set, then frozen
  (its version string goes into every runs file). Nobody tunes a prompt on gold-v1.
- Field meanings the prompt must state (the scorer relies on them): `value` is signed (a decrease is negative)
  and in `unit`, which should be one of spec §7's units (e.g. "USD millions", "%"); `company` is the company the
  answer is about, and for a "which company had more" question the one that had more; `citations` are passage
  ids as shown ("P1").
- This is a deliberately small format for the comparison; the full answer contract (spec §8) is W1-07.

2.5 Runs file (written by W1-13; format fixed in eval/runs_schema.py by W1-08): eval/results/model_runs/<run_id>.jsonl
----------------------------------------------------------------------------------------------------------------------
run_id = <M#>_<model>_<rag|closed>_think-<on|off>_<prompt version>, e.g. M1_qwen3-8b_rag_think-off_b0-v1.
One line per question:
    {"id": "B01", "run_id": "...", "raw_reply": "...", "parsed": {...B0 fields...} | null, "json_valid": true,
     "retries": 0, "prompt_tokens": 3954, "completion_tokens": 88, "latency_s": 2.4, "cached": false,
     "error": null}
The sidecar <run_id>.meta.json records model, endpoint (hosted/local), context (rag/closed), thinking,
temperature (0), max_tokens (1,024), prompt version, context-pack file and the sha256 of both pack files it read
(context_pack_sha256; the scorer refuses a run made from other packs) (eval.runs_schema.RunMeta; extra keys such
as the git commit are allowed). The runner writes records and meta with eval.runs_schema.RunRecord/RunMeta,
the scorer reads them with the same models (strict: a B0 reply with an extra field, or "2024" as a string year,
is invalid JSON for B0, i.e. parsed null). Runs files are committed so every reported number traces back to them.

2.6 Answer types and scoring (W1-08, implemented: python eval/score_answers.py)
-------------------------------------------------------------------------------
+------------------------------+-----------------------------------------------+--------------------------------------------+
| Answer type (mentor's split) | Gold items                                    | Correct when                               |
+==============================+===============================================+============================================+
| Short: numeric               | 48 = A fact 15 + B ratio 15 + C period 12 +   | value within the item's tolerance_pct of   |
|                              | F follow-up 6 (all F items carry a value)     | gold_value, units normalised (millions vs  |
|                              |                                               | billions) and the normalisation logged     |
| Short: entity                | D multi-company 10                            | the named company matches (and the value,  |
|                              |                                               | when the gold item has one)                |
| Summary                      | E qualitative 12                              | human grade 2 of 2 (0 wrong / 1 partly /   |
|                              |                                               | 2 correct and grounded), two graders;      |
|                              |                                               | LLM-as-judge rubric as a second opinion,   |
|                              |                                               | agreement reported                         |
| Refusal / not reported       | G 10 (7 refusals R1–R7 + 3 "not reported"     | refusals: refused with the right rule;     |
|                              | traps) + 22 refusal tests (13 refusals,       | traps: "not reported" and no value;        |
|                              | 7 controls, 2 partial)                        | controls answered; partials answer the     |
|                              |                                               | factual part and name the rule             |
+------------------------------+-----------------------------------------------+--------------------------------------------+
Details fixed in the scorer:
- short_numeric: the model's unit is converted to the gold unit (thousand/million/billion/trillion, "$B",
  "USD M"; % and ratio are not scaled). Also accepted, each logged in unit_note: a bare currency unit ("USD",
  "$") with the value already in the gold scale, a fraction for a percentage when the unit is not "%", and an
  unsigned value when the answer states the decrease in words. Otherwise the sign must match.
- short_entity: the gold winner per D item is D_WINNERS (the company the gold answer names last; a test checks
  it). The `company` field decides when it names one company, else the answer text when it names one; an
  answer naming both (or none) goes to the graders as a "grade" row instead of being marked wrong.
- refusal tests: kind refusal = refused with the expected rule; partial = not refused and refusal_rule set to
  the expected rule; control = not refused and no rule (controls have no gold value, so their content is not
  scored; a rule on a control is an over-refusal). A right decision with the wrong rule is wrong but gets no
  automatic label (W1-14 decides). Traps accept "not (separately) reported/disclosed" and "does not report".
- An answer with no reply (endpoint error) or invalid B0 JSON is wrong (malformed_output) and counted in table 5.
Hallucination checks (automatic): a number in answer/value found neither in the passages the run saw (none for a
closed-book run) nor in the gold answer or the conversation history the prompt showed. Two figures match at the
coarser of their printed precisions in any scale ("$391.0 billion" = 391,035 in millions; 44.65% = gold 44.6%);
a percentage only matches a percentage; the sign is ignored (text states it in words); dates (any format), bare
years, ordinals, footnote markers "(1)", Item/form/quarter names and passage ids are not figures; "10-12%" is two
percentages. Also: a value given for a "not reported" trap; fiscal_year or company different from the gold
item's; a cited passage id the run was not given ("[P1]" = "P1"). Refused answers are not checked. Known limit: a
RAG pack holds 100+ figures in four scales, so an invented round figure is often "supported" by chance; the check
measures grounding of figures, not every invention.
Output: eval/results/model_comparison.md (generated tables between markers + a hand-written interpretation
that re-runs keep): accuracy per model × answer type and per category, counts and Wilson 95% intervals (n is
10–48 per cell), hallucination checks (RAG vs closed-book), refusal precision/recall/rule, JSON validity, tokens,
latency p50/p95, failure labels, human-vs-judge agreement (exact and Cohen's kappa). Per run:
eval/results/scores/<run_id>.jsonl (every check per question).
Grading sheet for W1-14: one blind sheet for all runs, eval/results/grading/grading_sheet.csv
(key, task, question, gold_answer, model_answer, suggested_label, grader_1, grader_2, final, failure_label, note):
task "grade" = every summary answer and every D answer the scorer could not decide, "label" = every wrong
answer; a `final` of 2 on a label row overturns the automatic verdict (counted in the report). Rows are keyed by
"k" + a hash of run, question and answer text (the "k" keeps Excel from turning keys into numbers) and ordered by
key; model answers show no [Pn] markers or reasoning, and the key -> run mapping is in grading_key.csv (graders
do not open it). Re-running the scorer keeps every grade and label already entered; a graded row whose answer
changed (a new key) or that is no longer needed stays as task "stale", so no grade is ever applied to a
different answer. Grades are 0/1/2, labels from §2.7; latency percentiles leave out cached replies.
LLM-as-judge scores for summaries are imported from grading/judge_<run_id>.jsonl ({"id", "score", "reason"}),
written with the runner (W1-13).

3. Model comparison design (Sprint A)
=====================================
+----------+--------------------------------------+--------------------+------------------------------------------+
| Run      | Model                                | Context            | Question it answers                      |
+==========+======================================+====================+==========================================+
| M1 must  | Qwen3-8B (endpoint), thinking off    | RAG (context pack) | how good is the model we build on        |
| M2 must  | Llama-3.2-3B (local Ollama, 8k ctx)  | RAG (same pack)    | a smaller open model on identical inputs |
| M3 should| Qwen3-8B, thinking off               | closed-book        | how much it invents without retrieval    |
| M4       | Qwen3-8B, thinking on: DROPPED       | RAG                | not possible: the endpoint ignores the   |
|          |                                      |                    | thinking switch (§2.1); S2 chain-of-     |
|          |                                      |                    | thought in W1-09 covers reasoning        |
+----------+--------------------------------------+--------------------+------------------------------------------+
Same for every run: prompt B0, temperature 0, max_tokens 1,024, no tools (the Week 2 agent adds tools; this is
its baseline), one retry on invalid JSON.
Ollama gotcha (M2): the default context window (2–4k tokens) silently truncates our ~5k-token prompts. Create
a model with "PARAMETER num_ctx 8192" in a Modelfile (or set OLLAMA_CONTEXT_LENGTH=8192) and check on one long
prompt that the reply uses the last passage.
Budget: M1 and M3 102 calls each, judge ~40, all through the cache, one at a time; M2 runs locally in
parallel (no key; ~1–2 h on a CPU).
Caveats the report states: oracle filters (real accuracy will be lower until question-derived filters, W1-05),
small n per cell, a single frozen prompt.
