1. What Week 1 measured, and what it decides for the agent
===========================================================
- Retrieval decides most answers (ADR-017, ADR-018): with every gold figure in the passages, reasoning or
  decomposition gets 17/18 numeric questions right; without, every model fails. The agent searches with the
  company, year and fiscal period read from the question (retrieval/entities.py) and the financial statements
  first (the search_filings default); the reranker stays an opt-in setting (RETRIEVAL_RERANK) for latency.
- Numbers come from tools, not the model: arithmetic slips are the main loss when the evidence is present, and
  Qwen writes "$47.52 billion" as a wrong plain-dollar integer. The analyst step computes with calculate /
  compare_periods; the critic owns units.
- Refusal is decided first (ADR-018): reasoning and decomposition under-refused (S2 7, S3 8) because they started
  extracting; few-shot refusal examples fixed refusals (S1 20/20) but copied a real figure, so examples carry no
  real figures.
- Reasoning before a figure, not five samples: S2's reasoning field cut ungrounded numbers from 20/74 to 4/85,
  but five samples cost ~23 s per question; the planner and answer steps write a reasoning field once.
- Structured output and tools through the endpoint (ADR-016): json_schema guided decoding for every control-flow
  output (100% valid in Week 1), native tool calling for the four tools; get_financial_fact's metric becomes an
  enum first (the probe asked for 'net_sales').
- The answer leaves only through the contract and the critic (ADR-022): every number backed, calculations
  recomputed, company/year/period as asked, refusal policy; one send-back, then "could not verify".

2. Design: the LangGraph agent (W2-01 … W2-07)
===============================================
    question (+ earlier turns)
          │
          ▼
    ┌────────────┐  refuse (R1–R7) ───────────────────────────────────────────────┐
    │  PLANNER   │  entities (company, year, period) · plan: ordered tool steps   │
    └─────┬──────┘                                                                │
          │ Plan (JSON, guided)                                                   │
          ▼                                                                       │
    ┌────────────┐  search_filings (filters from the question, statements first)  │
    │  EXECUTOR  │  get_financial_fact (XBRL) · calculate · compare_periods       │
    │            │  guards: 10 steps, repeated call, token budget, 60 s           │
    └─────┬──────┘  tool error → back to the planner once (replan)                │
          │ tool results                                                          │
          ▼                                                                       │
    ┌────────────┐  draft answer with a reasoning field, citations = passage ids  │
    │  ANALYST / │ ◄──────────────────────────────────────────────────────────────┘
    │  COMPOSER  │  (a refusal: the §6 sentence)
    └─────┬──────┘
          ▼
    ┌────────────┐  check_contract (W1-07) + recomputed numbers + units
    │   CRITIC   │  fail → back to the executor once (a refusal: to the composer)
    └─────┬──────┘  fails again → "could not verify"
          ▼
    Answer (agent/contract.py: answer, value, unit, citations → SEC links, verified flag, refusal rule)

Refusals skip the executor; the composer writes them and the critic checks them like any answer (spec §8
invariant 5). State (agent/state.py, W2-01): question, earlier turns, limits, messages, entities, plan, tool calls
and results, draft answer, critic verdict, token and per-node run counters, errors (time: the run's 60 s limit and
AgentRun.seconds). Every LLM output that drives control flow is a pydantic model sent as json_schema (ADR-016)
with one retry on invalid JSON. Settings (existing, core/settings.py): MAX_AGENT_STEPS = 10, MAX_TOKENS_PER_QUERY =
12,000, QUERY_TIMEOUT_S = 60. Memory across turns (W2-06): a LangGraph checkpointer (in memory for now, with
serde=agent.graph.checkpoint_serde()) and retrieval.entities.from_turns for follow-ups. Tracing (W2-08): every
node and tool call in Langfuse, tagged with the question id; off in tests.

Around the graph: api/main.py (W2-09: POST /ask, GET /health, reply cache, rate limit; it awaits agent.graph.run
with one compiled graph shared by all requests) and ui/app.py (W2-10: chat, answer card with the verified badge
and citations, trace expander, disclaimer).
Evaluation (W2-11): eval/run_agent.py writes a RunRecord per question (with its tool calls) for the same scorer.

4. Process (as in Week 1)
=========================
- Branches w2/UPGRAD-<key>-<short-desc>; every commit message starts with the Jira key; one review by the
  ticket's backup; CI green before merge.
- Definition of done: tests offline and fast (fake LLM and fake tools; no key in CI), ruff clean, docs updated,
  PR reviewed.
- Prompts are tuned on the development set only and pinned by sha256 before any gold run; gold-v1 stays frozen.
- The shared key: one evaluation run at a time, through the reply cache; announce long runs in the team chat.
- Decisions with numbers go into docs/decisions.md (next free ADR: ADR-029; ADR-024 = the agent graph, W2-01;
ADR-025 = the planner, W2-02; ADR-026 = the tool schemas, W2-03; ADR-027 = the critic, W2-05;
ADR-028 = the executor, W2-04).

5. Risks
========
+--------------------------------------------+--------------------------------------------------------------+
| Risk                                       | Mitigation                                                   |
+============================================+==============================================================+
| Agent exceeds 60 s per question            | step cap 10, no multi-sampling, reranker off, timings traced |
| Tool calls with wrong arguments            | metric enum and clear schemas (W2-03), one replan on errors  |
| The critic rejects good answers            | each check tested on passing and failing cases; one retry    |
| Langfuse setup takes too long              | tracing optional in code; local JSON trace as a fallback     |
| Grading round 2 not done by Wed            | judge scores as the interim second opinion, stated as such   |
| Team availability                          | every ticket has a backup who reviews and can take it over   |
+--------------------------------------------+--------------------------------------------------------------+
