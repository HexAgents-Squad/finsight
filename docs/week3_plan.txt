1. What Week 2 measured, and what it decides for Week 3
=========================================================
(docs/report/week2_results_note.md, eval/results/agent_baselines.md, ADR-034, ADR-035)
- The agent is the system to ship: 42/48 numeric answers against B0's 16/48, all 102 answers 44 / 8 against B0
  (p ≈ 4×10⁻⁷), median 5.0 s and p95 12.4 s within the 60 s limit. Week 3 measures it, it does not rebuild it.
- What each part contributes is not measured yet: the plan's "compensating for a small model" section needs the
  ablations (W3-01) on the frozen A1 configuration, each paired with A1 by the sign test.
- The critic verified all 102 answers and caught none of the 16 wrong ones: six metric misses its metric check
  does not see (A06, B04, B08, B14, B15, C08, each on a line item the facts tool has no metric for), three refusal
  errors (RF10, RF13, RF14) and seven weak summaries. W3-02 fixes the checks and the metrics as a new version, A5,
  tuned on the development set first; A1 stays the baseline the ablations are measured against.
- Summaries are the weakest answer type (5/12, B0 8/12); the LLM judge is lenient against the graders (kappa
  0.10-0.29), so any new summary score needs the graders.
- Safety holds at the agent level (0/12 injections, planted text kept from the model, PII masked); W3-05 shows it
  through the API, the way a user meets the system.

3. What each ticket delivers (acceptance in Jira)
=================================================
W3-01 Ablations (eval/run_agent.py --ablation, run ids A2-A4). Each turns one component off on the A1
  configuration, otherwise unchanged (same questions, scorer, tolerances, prompts): A2 no calculator (the composer
  reads figures, the critic recomputes nothing), A3 no critic (the draft is the answer), A4 no statements-first
  retrieval (plain hybrid search). Offline tests for the switch; runs through the reply cache (an unchanged call
  replays free); each scored by eval/score_answers.py and paired with A1 by the sign test in
  eval/results/agent_ablations.md. A3's expected null result (the critic changed no answer in A1) is itself a
  finding. Requests: about 170 on the shared key (estimates in eval/results/agent_baselines.md: A2 ~140, since
  removing the calculator changes the planner's tool list and so every planner call, plus the composer on the 34
  calculations; A3 ~0, all calls replay; A4 ~30, the composers after a search).
W3-02 Version A5 (agent/critic.py, tools/financial_facts.py, config/concept_map.yaml): the metric check learns the
  line items A1 missed (deposits, noninterest expense, current assets and liabilities, segment figures, net sales
  apart from total revenue, the medical cost ratio); for an operation every fetched metric must be named by the
  question or be its denominator; SEARCH_ONLY rejects only the substituted metric; the facts tool gains the XBRL
  metrics it lacked. A new metric changes the tool schemas and so the planner's pinned inputs (ADR-025, ADR-026):
  re-pin them, and re-extract the XBRL facts if a concept is new. Critic checks first (they need no new data), then
  the metrics. Tuned on the development set (no gold question read), offline tests on the nine answers' shapes,
  then one gold run A5 scored next to A1 (about 190 requests) if the development results hold by Tue 24 noon.
  ADR-036.
W3-03 Evaluation report (eval/report.py → eval/results/evaluation_report.md, its charts and a PDF): accuracy by
  answer type per system version (B0 → best strategy → A1 → A5, with the ablations), the failure taxonomy of the
  plan (retrieval miss, reasoning error, tool-call error, hallucination, refusal error) mapped from the graders'
  labels and drawn as a stacked bar per version, task completion, tool calls and retries per task, citation
  accuracy (the cited section contains the fact; project plan §9.2), tokens, latency p50/p95 and cache hit rate.
  Generated from committed results only (tests, as for the Week 1 and 2 notes).
W3-04 Trace dashboard: the 10 demo queries and A1's 16 wrong answers run traced in Langfuse (tags q:<id>,
  run:<run_id>); scripts/trace_dashboard.py output committed in eval/results/traces/; screenshots of the trace list
  and of one trace (planner → tools → composer → critic) in docs/screenshots/w3-04/; the dashboard link for the
  submission. Requests: about 60 (the demo and the failures, through the cache where unchanged).
W3-05 Safety through the API: the 12 injection tests and the 22 refusal tests sent to POST /ask; PII prompts with
  their API log lines and trace shown masked; rate limit and cache shown (429 with Retry-After, a cache hit);
  docs/responsible_ai.md (intended use, failure modes, refusals, adversarial tests, human-in-the-loop, limits,
  with the evidence of each), the report's responsible-AI section. Requests: about 40.
W3-06 Deployment: docker-compose.yml (api, ui, and Langfuse as an optional profile), the index and XBRL facts mounted
  as volumes, secrets only in .env; a Makefile (make ingest, index, eval, test, up, down); README steps from a clean
  clone to a running UI; health checks; a second member brings it up on a clean machine and records the time.
W3-07 Report (docs/report/final_report.md → PDF, 12 pages, outline in the project plan §13): problem and scope,

4. Process (as in Weeks 1 and 2)
================================
- Branches w3/UPGRAD-<key>-<short-desc>; every commit message starts with the Jira key; one review by the
  ticket's backup; CI green before merge; a clean-clone run before a push.
- Definition of done: tests offline and fast (fake LLM and fake tools; no key in CI), ruff clean, docs updated,
  PR reviewed by the backup.
- gold-v1 stays frozen; prompts are tuned on the development set only and pinned before a gold run; A1 is the
  frozen baseline of the ablations.
- The shared key: one run at a time, through the reply cache, announced in the team chat; the week's estimate is
  about 460 requests (W3-01 170, W3-02 190, W3-04 60, W3-05 40), agreed before the first run.
- Decisions with numbers go into docs/decisions.md (next free ADR: ADR-036; the Week 2 notes stop at ADR-035).
