2.1 Section document: data/sections/sections.jsonl (WP2 → WP5, WP4)
-------------------------------------------------------------------
One JSON object per line = one "document":
    {"doc_id": "AAPL_10-K_2024_Item7", "ticker": "AAPL", "cik": "0000320193", "sector": "tech",
     "form": "10-K", "fiscal_year": 2024, "fiscal_period": "FY", "period_end": "2024-09-28",
     "filing_date": "2024-11-01", "accession_no": "0000320193-24-000123",
     "item": "Item 7", "item_title": "Management's Discussion and Analysis ...",
     "source_url": "https://www.sec.gov/Archives/edgar/data/...", "source_location": "main document",
     "text": "...", "n_chars": 41234, "has_tables": true}
- item naming is exactly "Item 1", "Item 1A", "Item 7", "Item 8"… (10-Q: "Part I Item 2" etc.). The gold set
  uses the same names.
- doc_id for a 10-Q carries the quarter and the Part: "AAPL_10-Q_2025Q1_PartIItem1".
- has_tables is true when the text contains a flattened table row (" | "); it is a hint, not a table count.
- Section-mapping rule (docs/spec.md §3): text that sits in an exhibit (e.g. a bank's Exhibit 13 annual report)
  or behind a cross-reference index is labelled with the Item the filing's cross-reference index assigns it;
  source_location records where it physically came from ("main document", "Exhibit 13", …) and source_url
  points at that file.
- Day 2: WP2 commits data/sample/sections_sample.jsonl (2 companies, hand-checked) so WP5 can start.

2.2 XBRL cache (WP3 → WP6)
--------------------------
data/xbrl/<TICKER>.json = raw SEC companyfacts JSON. config/concept_map.yaml maps our metric names (revenue,
operating_income, net_income, rd_expense, capex, total_assets…) to XBRL concepts.

2.3 Tool signatures (WP6)
-------------------------
    calculate(operation: ratio|percent|growth|difference|sum|cagr, inputs: [float], years?: float) -> {operation, inputs, result, unit, expression}
    get_financial_fact(ticker, metric, fiscal_year, fiscal_period="FY", duration?: 3M|6M|9M|12M) -> {value, unit, ticker, fiscal_year, fiscal_period, duration, period_start, period_end, concept, accession_no, filed, url}
    compare_periods(ticker, metric, years: [int]) -> [{fiscal_year, value, unit, period_end, yoy_growth_pct}]
    search_filings(query, ticker?, fiscal_year?, fiscal_period?, form?, item?, k=5) -> [{chunk_id, text, ticker, form, fiscal_year, fiscal_period, item, source_url, score}]
Errors are returned as structured "not found" results (never crash), so the agent can replan.
Outputs carry the fields the answer contract (docs/spec.md §8) needs, so the composer copies them without
re-typing. get_financial_fact: duration defaults to 12M for FY and 3M for quarters (spec §4.2); point-in-time
facts return duration null. Currency values are scaled to the unit the company's statements use (spec §7.3).
Formulas and undefined cases for calculate are fixed in spec §7.2.

2.4 Gold item: eval/gold_set.jsonl (WP4 → WP5/WP8 and later all evaluation)
---------------------------------------------------------------------------
    {"id": "B07", "category": "ratio", "question": "...", "companies": ["MSFT"], "fiscal_years": [2024],
     "gold_answer": "...", "gold_value": 44.6, "unit": "%", "tolerance_pct": 1.0,
     "gold_sources": [{"ticker": "MSFT", "form": "10-K", "fiscal_year": 2024, "fiscal_period": "FY", "item": "Item 8"}],
     "must_refuse": false, "refusal_rule": null, "previous_turn_id": null,
     "written_by": "Anirudh", "verified_by": "Chandra Shekhar"}
ID = category letter + 2 digits: A fact · B ratio · C period comparison · D multi-company · E qualitative · F
multi-turn · G refuse / not answerable.
- fiscal_period in gold_sources: "FY" for 10-K, "Q1"/"Q2"/"Q3" for 10-Q.
- refusal_rule: "R1"…"R7" (docs/spec.md §6) when the expected answer is a full or partial refusal, else null.
  G items are either refusals (must_refuse true, refusal_rule set, no gold_sources) or "not reported" traps
  (must_refuse false, refusal_rule null, gold_answer "not reported", no gold_value, and gold_sources = the
  section where the figure would appear, e.g. Item 8, because a non-refused answer must cite what it checked).

Writing rules (summary):
1. Open the filing on EDGAR, write the question as an analyst would, and copy the exact figures (note
   units: millions or billions).
2. Compute ratios in a spreadsheet; record gold_value, unit and tolerance_pct.
3. Always fill in gold_sources (ticker, form, fiscal year, Item), because recall@k depends on it.
4. Mention the fiscal-year end when it is not December (Apple ~Sep, Microsoft Jun, NVIDIA ~Jan, Walmart
   Jan).
5. G (refuse): at least one question per refusal rule R1–R7 in docs/spec.md §6 (investment advice, forecasts,
   out of corpus, valuation opinions, personal data, rule-breaking instructions, off-topic), each with its
   refusal_rule, plus 2–3 "trap" questions that look answerable but aren't in the filings (refusal_rule null,
   gold_answer "not reported").
6. Verification: the verifier re-opens the filing, checks every number and source, then sets verified_by.
   Disagreements go to the group; nobody edits someone else's question silently.
7. Collect in a shared Google Sheet first (easier for 5 people), then Alok converts it to gold_set.jsonl
   with eval/sheet_to_jsonl.py and runs eval/validate_gold.py.

Freeze: Thu 5 Nov EOD → validator passes in --final mode → git tag gold-v1 → no edits afterwards (corrections
only through a reviewed PR that bumps the version).

WP2 – Corpus: download + split into Item sections  (Chandra Shekhar, backup Alok)
---------------------------------------------------------------------------------
Output: ingest/01_download.py, ingest/02_parse_sections.py, data/raw/manifest.jsonl,
        data/sections/sections.jsonl, data/sections/parse_report.csv, data/sample/sections_sample.jsonl
Download
1. Put SEC_USER_AGENT="HexAgents_Squad <your email>" in .env (the SEC requires a contact). Stay under 10
   requests/second (sleep ~0.15 s between calls), save everything to data/raw/, skip files already there.
2. Ticker → CIK: https://www.sec.gov/files/company_tickers.json (pad CIK to 10 digits).
3. Filing list: https://data.sec.gov/submissions/CIK##########.json → filings.recent has form,
   accessionNumber, reportDate, filingDate, primaryDocument. Banks file thousands of documents, so also read
   the older pages listed in filings.files, or their 2023–2024 10-Ks will be missing.
4. Fiscal year: use the company's own label, NOT the calendar year of reportDate. In the XBRL company-facts
   file (WP3) every fact row has accn + fy + fp, so you can map accession number → (fiscal year, period).
   The calendar year is wrong for Apple, Microsoft, NVIDIA and Walmart.
5. Select one 10-K for each fiscal year 2023, 2024, 2025 and the 10-Qs of fiscal 2025 → expect 120 filings.
6. Document URL: https://www.sec.gov/Archives/edgar/data/{cik}/{accession-without-dashes}/{primaryDocument}.
   Write one manifest line per filing (ticker, form, fiscal_year, fiscal_period, dates, accession, URL, path).
Parse
7. HTML → text with BeautifulSoup (lxml): remove script/style and the hidden inline-XBRL header
   (ix:header / display:none); turn every table row into "cell | cell | cell"; normalise whitespace.
8. Split on lines that START with "Item <n>". 10-K items: 1, 1A, 1B, 1C, 2, 3, 4, 5, 6, 7, 7A, 8, 9, 9A, 9B,
   9C, 10–16. 10-Q: Part I Items 1–4, Part II Items 1, 1A, 2–6 (key "Part I Item 2").
9. Pitfalls to handle and test:
   - Every heading appears twice (table of contents + body): keep the occurrence with the longest section.
   - Table-of-contents rows end with a page number ("Item 7. | MD&A | 23"): ignore them.
   - Some filers repeat a bare "Item 7" as a page header on every page: accept a bare "Item N" line only if
     the next line is that Item's title.
   - 10-Q item numbers repeat in Part I and Part II: work out the Part from the title.
   - Some filers put the MD&A or financial statements outside the Item headings (after Item 15, in a separate
     annual-report document in the same filing folder, or with no Item headings at all). Check the banks
     (JPM, WFC, C, BAC) and NVIDIA closely: if Item 7 or Item 8 is only a short pointer ("see page 50"),
     locate the "Management's discussion and analysis" and "Report of Independent Registered Public
     Accounting Firm" headings and label those regions Item 7 and Item 8.
10. Drop sections under ~300 characters ("Not applicable"). Write sections.jsonl (schema §2.1) and a
    parse_report.csv (items found per filing).
11. Checks: all 60 10-Ks have Item 7 and Item 8 longer than 3,000 characters; total documents between 500 and
    2,000; the backup opens 10 random sections next to the original HTML.
12. Sat 31 Oct: commit data/sample/sections_sample.jsonl (2 companies) so WP5 can start.
Tip: you may try the edgartools library first; if its splits are wrong on the banks, use your own parser.
Record the choice in docs/decisions.md.

4. Selection rule for an annual value: form 10-K, fp = FY, duration about one year (330–400 days) or instant;
   then, within each filing, take the row with the LATEST end date. A 10-K also repeats last year's figures
   with the same fy label, so without this rule you return the prior year. If a 10-K was amended, keep the
   most recently filed value.
   Quarterly values (fiscal_period Q1–Q3, needed by the §2.3 contract): form 10-Q, fp = Q1/Q2/Q3, then pick by
   duration: 3M ≈ 80–100 days (the default), 6M ≈ 170–190 days, 9M ≈ 260–280 days (year-to-date), and again
   the row with the latest end date within the filing (10-Qs repeat the prior-year quarter). Balance-sheet
   items are instants (duration null). Q4 is never derived (spec §4.2).
5. Build the coverage matrix (metric × company × year). Close gaps only with concepts that mean the SAME thing
   (e.g. banks report "total net revenue": RevenuesNetOfInterestExpense; "cash and due from banks"). Some
   companies simply don't report a metric (banks and several pharma companies have no operating income): write
   these gaps in docs/decisions.md and never substitute a different quantity.
6. Spot-check at least 5 values against the income statement in the 10-K (e.g. Apple FY2024 revenue).
